#### 1.4.3 Описание бизнес-процесса "Создание сессии испытаний по образцам"

##### 1.4.3.1 Предусловия

- Известен список образцов, которые будут обрабатываться в рамках испытаний (с номерами/ID). Эти образцы промаркированы и доступны для отбора.
- У оператора нет другой активной сессии испытаний.

##### 1.4.3.2 Логическая последовательность выполнения функций

**Триггер:** Оператор или интеграционная система (UI правой панели, админка или LIMS) инициирует создание новой сессии испытаний, передавая список образцов и свои данные.

**Ход процесса:**
1. Пользовательский интерфейс отправляет `POST /sessions` с параметрами:
   - `operatorName`
   - массив `sampleOrder[]` в порядке проведения испытаний
2. Система создаёт запись `SESSION`, фиксирует начальный шаг.
3. Система создаёт записи `SESSION_SAMPLE` по каждому образцу и пустыми значениями масс и плотности.
4. Система формирует предопределённый список шагов для правой панели:
   - Приветствие.
   - Перенести образец №N на весы (по каждому образцу).
   - Назвать массу и подтвердить (по каждому образцу).
   - Расчёт результатов.
   - Завершение.
5. Система возвращает в ответе:
   - `sessionId`
   - список образцов с начальными статусами
   - структуру прогресса шагов
   - текущий шаг

##### 1.4.3.3 Постусловия / Ожидаемый результат

- Создана новая сессия с уникальным `sessionId`.
- Записан список образцов, закреплённых за сессией, с начальными статусами и пустыми результатами.
- В журнал пользователя добавлено событие `session_start`.
- Пользовательский интерфейс получил структуру для отображения в правой панели (шаги, прогресс, список образцов).
- В случае ошибок система вернула соответствующий код и описание, а сессия не была создана.

#### 1.4.4 Метод "Создать сессию испытаний по образцам"

##### 1.4.4.1 Логика работы метода

**Валидация входных данных:**
- `operatorName` — обязательный параметр.
- `sampleOrder` — обязателен, массив от 1 до N; без дублей.

**Создание записей:**
- Создать `SESSION`:
  - `status = 'active'`
  - `current_step = 'greeting'`
  - `samples_total = len(sampleOrder)`
  - `voice_mode = 'manual_weight'`
- Для каждого `sampleId` создать `SESSION_SAMPLE` со статусом `pending`, `m1..m3 = null`, `density = null`, порядковый номер — по `sampleOrder`.
- Создать предопределённый статический список шагов для прогресс-панели: `greeting → done=false`, `take_sample / say_mass_and_confirm` для каждого образца в порядке `sampleOrder`, `compute_results`, `finish`.

**Инициализация прогресса:**
- `greeting.done = true` (сразу после старта).
- `samplesDone = 0`, `samplesTotal = len(sampleOrder)`.

**Формирование ответа:**
- Вернуть `sessionId`, список образцов, текущий шаг (`greeting`), структуру `progress.steps[]` (статический список) и счетчики прогресса.
- Метод ничего не рассчитывает (ни плотности, ни финал) — только создаёт каркас сессии. Формат ответа описан в «Спецификации» ниже.

#### 1.5.3 Описание бизнес-процесса "Получение состояния сессии испытаний для отображения в правой панели"

##### 1.5.3.1 Предусловия

- Сессия испытаний создана в системе (есть `sessionId`): см. [1.API] Постановка задачи "POST/sessions – Создать сессию испытаний по образцам".
- Список образцов (с их идентификаторами) закреплён за сессией в порядке проведения.
- В базе данных хранятся:
  - Данные по введённым и подтверждённым массам (`m1`, `m2`, `m3`) для каждого образца.
  - Данные по рассчитанной объёмной плотности (если уже вычислена).
  - Итоговые фактические результаты (если расчёт финальных результатов уже выполнен).

##### 1.5.3.2 Логическая последовательность выполнения функций

**Триггер:** Запрос от пользовательского интерфейса (правой панели) или внешней системы на получение актуального состояния сессии по `sessionId`.

**Последовательность:**
1. Пользовательский интерфейс отправляет запрос `GET /sessions/{sessionId}`.
2. Система валидирует входные параметры (`sessionId`).
3. Система загружает из базы:
   - Данные о сессии и её статусе.
   - Список образцов с их массами и рассчитанными плотностями.
   - Итоговые результаты (если есть).
4. Система определяет текущий шаг сценария (где находится пользователь):
   - Приветствие.
   - Перенести образец №N на весы.
   - Назвать массу и подтвердить.
   - Рассчитать результаты.
   - Завершение.
5. Система рассчитывает прогресс:
   - Количество образцов с рассчитанной плотностью.
   - Общее количество образцов.
   - Признак `done` для каждого шага в статическом списке шагов.
6. Система формирует ответ с полной структурой состояния сессии.
7. Система отправляет ответ в пользовательский интерфейс.
8. Интерфейс отображает актуальные данные в правой панели.

##### 1.5.3.3 Постусловия / Ожидаемый результат

- Пользовательский интерфейс получает актуальное состояние сессии:
  - Текущий шаг сценария.
  - Прогресс по каждому образцу.
  - Список шагов с их статусами `done`/`false`.
  - Итоговые результаты, если расчёт уже выполнен.
- При позитивном сценарии — правое информационное поле обновлено.
- При негативных сценариях — UI получает код и описание ошибки и отображает сообщение пользователю.

#### 1.5.4 Метод "Получить состояние сессии"

##### 1.5.4.1 Логика работы метода

**Валидация входных данных:**
- Извлечь `sessionId` из пути. Если формат некорректен → 400.

**Загрузка состояния сессии:**
- Найти запись `SESSION` по `sessionId`. Если не найдена → 404.
- Загрузить связанные записи `SESSION_SAMPLE` (список образцов в заданном порядке).
- По каждому образцу получить зафиксированные массы `m1`, `m2`, `m3` и рассчитанную `density` (если есть).

**Определение текущего шага (для правой панели):**

Шаги считаются статическим списком и заполняются по факту выполнения. Итерации по образцам — в порядке, заданном в сессии:
- `greeting` — Приветствие (выполнено после старта сессии).
- `take_sample` — «Перенесите образец №N на весы» — для каждого образца.
- `say_mass_and_confirm` — «Назовите массу и подтвердите» — для каждого образца.
- `compute_results` — «Расчёт результатов».
- `finish` — «Завершение».

**Логика выбора текущего шага:**
- Если `greeting` уже проставлен на этапе создания сессии, то сразу перейти к следующему шагу `take_sample(sampleId=1)`.
- Если есть первый образец без рассчитанной `density`:
  - Если по нему нет ни одной подтверждённой массы → текущий шаг `take_sample(sampleId=N)`.
  - Иначе (есть, но <3 подтверждённых масс) → текущий шаг `say_mass_and_confirm(sampleId=N)`.
- Если все образцы имеют рассчитанную `density`, но финальный результат ещё не посчитан → `compute_results`.
- Если посчитан финальный результат → `finish`.

**Подсчёт прогресса:**
- `samplesDone` = число образцов, у которых заполнены все 3 массы и рассчитана `density`.
- `samplesTotal` = количество образцов в сессии.
- Проставить `done=true` у шагов:
  - `greeting` — всегда `true` после старта;
  - для каждого `take_sample` / `say_mass_and_confirm` по образцу — на основании наличия подтверждённых масс;
  - `compute_results` — `true`, если финальный расчёт выполнен;
  - `finish` — `true`, если сессия завершена.

**Формирование ответа:**
- Вернуть объект состояния сессии: текущий шаг, список шагов прогресса (статический список с привязкой к `sampleId` для шагов 2–3), список образцов с их статусами и массами, счётчики прогресса.

##### 1.5.4.1.1 Маппинг данных для сохранения

Метод GET — сохранение отсутствует (Н/Д).

##### 1.5.4.1.2 Маппинг данных для получения

| № | Название параметра (выход) | Преобразование/логика | Поле БД (источник) |
|----|----------------------------|------------------------|---------------------|
| 1 | sessionId | Прямое значение. | SESSION.ID |
| 2 | step.code | Вычислить по п.4 логики. | Производное (на основании таблиц ниже) |
| 3 | step.sampleId | Если шаг относится к образцу. | Производное |
| 4 | samples[].id | Прямое значение. | SESSION_SAMPLE.SAMPLE_ID |
| 5 | samples[].masses.m1 | Подтверждённое значение или null. | SESSION_SAMPLE.M1 |
| 6 | samples[].masses.m2 | Подтверждённое значение или null. | SESSION_SAMPLE.M2 |
| 7 | samples[].masses.m3 | Подтверждённое значение или null. | SESSION_SAMPLE.M3 |
| 8 | samples[].density | Значение, если рассчитано, иначе null. | SESSION_SAMPLE.DENSITY |
| 9 | samples[].status | `pending` / `in_progress` / `done` (правило ниже). | Производное |
| 10 | progress.samplesDone | Кол-во образцов с заполненными m1..m3 и density. | Агрегация SESSION_SAMPLE |
| 11 | progress.samplesTotal | Размер списка образцов. | Агрегация SESSION_SAMPLE |
| 12 | progress.steps[] | Статический список шагов с признаками done. | Производное |
| 13 | final | Итог (если посчитан): avgDensity, delta. | SESSION.FINAL_AVG_DENSITY, SESSION.FINAL_DELTA (опц.) |

**Правило `samples[].status`:**
- `pending` — по образцу нет подтверждённых масс;
- `in_progress` — подтверждены одна/две массы, `density` ещё нет;
- `done` — подтверждены три массы и рассчитана `density`.

##### 1.5.4.1.3 Обработка ошибок

| Код | Текст | Условие |

#### 1.9.3 Описание бизнес-процесса "Создание сессии испытаний по образцам"

##### 1.9.3.1 Предусловия

- Сессия испытаний создана и находится в статусе `active`.
- Все образцы, закреплённые за сессией, имеют рассчитанную объёмную плотность (`density`) и статус `done`.
- Финальный результат по сессии ещё не рассчитывался (`finalComputed=false`).
- Сессия ещё не завершена (`status != finished`).

##### 1.9.3.2 Логическая последовательность выполнения функций

**Триггер:** Оператор или система инициирует расчёт итоговых показателей после завершения обработки всех образцов, вызывая метод `POST /sessions/{sessionId}/compute-final-results`.

**Ход процесса:**
1. Клиент отправляет запрос с указанием `sessionId`.
2. Система валидирует:
   - сессия активна,
   - у всех образцов есть рассчитанные плотности,
   - итог по сессии ещё не вычислялся.
3. Система извлекает из БД список плотностей всех образцов.
4. Система выполняет расчёт:
   - среднего арифметического (`avgDensity`),
   - разницу результатов (`delta`).
5. Система сохраняет рассчитанные значения в записи сессии (`SESSION.FINAL_AVG_DENSITY`, `SESSION.FINAL_DELTA`).
6. Система устанавливает флаг `finalComputed=true`.
7. Система отмечает шаг `compute_results` как `done`.
8. Система обновляет статус сессии на `finished`.
9. Система фиксирует дату и время завершения (`finishedAt`).
10. Система блокирует возможность внесения изменений в образцы и результаты.
11. Система возвращает рассчитанные показатели и обновлённый прогресс.

##### 1.9.3.3 Постусловия / Ожидаемый результат

- Рассчитаны и сохранены итоговые показатели: `avgDensity`, `delta`.
- Флаг `finalComputed` установлен в `true`.
- В прогрессе шаг `compute_results` отмечен как `done`.
- Статус сессии изменён на `finished`.
- Дата завершения зафиксирована в БД.
- Возможность изменения данных по сессии заблокирована.
- Пользователь получил рассчитанные показатели и обновлённый прогресс.
- При ошибках данные в сессии не изменяются, возвращается код ошибки и описание.

#### 1.9.4 Метод "Рассчитать фактический результат испытаний (после всех образцов)"

##### 1.9.4.1 Логика работы метода

**Валидация входных данных:**
- `sessionId` должен существовать и соответствовать активной сессии.
- Все образцы в сессии должны иметь рассчитанную `density` (статус `done`).
- Итоговый результат по этой сессии ещё не должен быть рассчитан.
- Сессия ещё не должна иметь статус `finished`.
- Если хотя бы у одного образца нет плотности — вернуть 422.

**Получение данных:**
- Извлечь плотности всех образцов (`density[]`).
- Количество плотностей должно совпадать с `samplesTotal`.

**Расчёт итоговых показателей:**
- Выполнить расчёт среднего арифметического по установленной формуле.
- Выполнить расчёт разница результатов по установленной формуле.

**Сохранение результата:**
- Записать `avgDensity` и `delta` в `SESSION.FINAL_AVG_DENSITY` и `SESSION.FINAL_DELTA`.
- Обновить признак завершения расчётов (`finalComputed=true`).

**Обновление прогресса:**
- Установить шаг `compute_results.done = true` в прогрессе сессии.

**Закрытие сессии**
- Обновить статус сессии на `finished`.
- Зафиксировать дату и время завершения (`finishedAt`).
- Заблокировать возможность внесения изменений в образцы и результаты.

**Формирование ответа:**
